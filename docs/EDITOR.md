# The editor

**Lunaris Editor is a Windows application**, like the editors of the other engines: a real window with a menu bar, a toolbar, a hierarchy, a scene view drawn by the engine's own GPU renderer, an inspector, a project browser and a console. It is not a web page.

```
lunaris-editor.exe                              (or double-click "Lunaris Editor.bat" in the project folder)
lunaris-editor.exe examples/echo_tour.lunaris.json
lunaris edit examples/echo_tour.lunaris.json    (the same, started from the command line)
```

Build it with `cargo build --release -p lunaris-studio` (the program is `target/release/lunaris-editor.exe`). It is made with egui (the window and the panels) over the same wgpu the engine draws with.

## The layout (Unity's)

| Panel | What it does |
|---|---|
| **Menu bar** | File (new, open, save, save as: the system's own file dialogs), Edit (undo, redo, duplicate, delete), Entity (create anything), View, Play, Help |
| **Toolbar** | The tools of the scene view: Hand (Q), Move (W), Rotate (E), Scale (R); in the middle Play, Pause, Step; Undo and Redo |
| **Hierarchy** (left) | The scene's name and every entity below it, children under the entity they are attached to. Click selects, **Ctrl+click adds an entity to the selection or takes it out, Shift+click selects the range from the last selected one**, double-click renames, drag one onto another to attach it (it keeps its place), right-click for duplicate, delete, detach, create (on a row that is selected with others, duplicate and delete act on all of them). The search box filters |
| **Place** (the second tab of the left panel) | Unreal's Place Actors: everything the Entity menu can make as rows under headings (Basic, 3D Object, Light, 2D, UI, Audio, Effects) with a search box. **Click** a row to add the thing in front of the camera; **drag** it into the scene view to add it where it is dropped, standing on whatever is under the pointer (a cube, sphere or cylinder rests on the surface, a point or spot light hangs 2 m above the point, a camera 1.5 m). While you carry it, the view gets an outline and a ring and a label show where it will land. See "The Project panel" below for how the drop finds its point |
| **Scene** / **Game** (middle) | Scene: a free camera (right button drag looks, right button + W A S D Q E flies (Shift is three times faster; with the right button held the wheel sets the speed, a tenth to ten times the usual), middle drag pans, wheel zooms, Alt + left drag orbits, F frames the selection) drawn by the GPU renderer; click selects (also cameras and lights, which have no picture; Ctrl+click adds to the selection or takes out of it); the handles of the tool drag the selection along an axis (Ctrl snaps; Shift scales all three axes). The toolbar above the view picks the render quality (Classic ... Ultra, or the CPU reference renderer), 2D mode, grid, gizmos and **Stats**, a corner overlay with the editor's frame time and fps, what the last picture cost, the number of entities, the tick and the fly speed. Game: what the scene's own camera sees, with input going to the game while playing |
| **Inspector** (right) | The selected entity's components, one bar each (click to fold, right-click to remove): every field as the right kind of widget (drag boxes, colour pickers, check boxes, drop-downs, asset pickers), rotation as angles. Add Component at the bottom. The fields come from the engine's `schema`, so a component defined by a game shows up with no editor code |
| **Project** (bottom, with the Console, Systems and Profiler tabs) | The workspace as folders on the left and tiles on the right: a picture's tile shows the picture, a model's tile a small picture of the model and a sound's tile its waveform (all made in the background), double-click a scene to open it; **drag a model, a picture or a sound into the scene view**, or right-click it to use it; a search box and a **type menu** (All types, Scenes, Models, Pictures, Sounds) narrow the tiles, from every folder, to what matches |
| **Console** | Everything the editor asked the engine (every click is a tool call; hover for the arguments and the answer), errors in red, search, "Check scene" (the `check` tool), and a box where you can type any tool call |
| **Systems** | The systems that run every tick. A graph system is drawn as **nodes** (a red event node on top, white execution wires down through the statements, green, red and magenta data wires from the expressions into the pins that use them; wheel zooms, drag pans, Fit shows it all), next to its JSON; click a constant in the picture to change its value, edit the text, then **Apply** (`define_system`; the engine's error comes back with its path). Systems can be switched on and off with their check box |
| **Profiler** | Where the time of each tick goes **while the game plays** (Unreal's `stat` views and Insights, for the game thread): the average and slowest tick, what share of a 60 Hz tick that is and how many times over it would fit (headroom), a graph of the last two minutes with the 60 Hz line, one bar per stage of the tick (movement, physics, each graph system, ...) slowest first with its average, share and worst time, and the same advice the `profile` tool gives ("`physics` is 61% of the time: start there"). A window is one second of game time. *Freeze* keeps the numbers on screen, *Filter* narrows the stages. The simulation times itself **only while this tab is showing** (a closed tab costs nothing); the numbers are wall-clock times of this machine and never part of the state |

**Play** saves the scene in a snapshot and runs the simulation at 60 ticks a second inside the editor, with sound and with the keyboard and mouse going to the game when the pointer is over the Game view. **Stop** (or Esc) puts the scene back exactly as it was (the state hash is the same). Edits made while playing are thrown away with the run.

## The look (Unreal Editor 5's dark theme)

The editor's palette and furniture follow the Unreal Editor's, measured from the screenshots in Epic's own documentation (the editor layout page, the Content Browser, the Place Actors panel, the Sequencer and the Material editor pages): panels `#242424`, menu bar `#161616`, toolbars `#111111` and `#171717`, tab strips `#1a1a1a`, fields `#0f0f0f`, bands (a category in the Details panel, the header and the status line of a list) `#2f2f2f`, list rows striped `#1a1a1a` and `#151515`, a slate-blue selection `#40576f`, text `#c0c0c0` and dimmer `#808080` (`theme.rs`). On top of the colours: the **Hierarchy** is Unreal's Outliner (an "Item Label" and "Type" header, striped rows, a type column, a status line "788 entities (2 selected)" under the list, and **an eye column**: the eye of a row with a mesh, or with meshes attached under it, shows or hides all of them (`MeshRenderer.visible` of the whole subtree in one `batch` call, so one Undo takes it back; a hidden row is dimmed, the eye is closed); the **Inspector** is the Details panel (a search pill that narrows the fields, categories as bold bands, striped property rows, the edges of the X, Y and Z boxes red, green and blue instead of letters, and **a reset arrow** after every value that is not the one a new component starts with, which puts it back (one undo step; the values come from the `defaults` that `schema` gives for a component); the **Place** tab has Unreal's cards (a dark plate with the kind, the name after it, the category's name centred in capitals); the **Project** panel puts a colour bar under each thumbnail by kind (a model teal, a picture red, a sound amber, a scene blue) and counts its items; the **scene toolbar** has Unreal's pills (dark rounded buttons with a thin outline, lighter when on, an arrow on the drop-downs); the **toolbars** are flat (a box only under the pointer), the tool that is on is a bright blue picture and Play is green; the **Console** is laid out as Unreal's Output Log (a Filters pill with Tool calls, Messages and Errors, a "Search Log" pill, one monospaced line per message with a `LogTool`, `LogEditor` or `LogError` category and the answer and time dimmed after it, a "Cmd" box under the list); the **status bar** starts with Unreal's two buttons, Content Drawer and Output Log, which open and close the bottom panel on the Project tab and the Console; the **Sequencer** has the red playhead with its pentagon head and a darker area after `end`. Nothing here is Unreal's code or artwork.

## Selecting several things

Ctrl+click in the Hierarchy or the scene view, or Shift+click a range in the Hierarchy, selects several entities. The one selected **last** is the main one: the Inspector shows it (and says how many are selected), the handles sit on it, the Blueprint and Sequencer tabs follow it. What acts on all of them: **dragging the Move handle** (the others move by the same amount along the same axis; Ctrl snaps the main one as before), **Duplicate** and **Delete** (Edit menu, Ctrl+D, Delete, the Hierarchy's menu; an entity inside another selected entity goes with it and is not done twice), **Frame** (F: the middle of them all) and the outlines in the scene view (the main one bright, the others dimmer). Rotate and Scale (the handles) act on the main one only. The Inspector shows the main one, and **a value you change there** (a position, a colour, any field) **is written to every selected entity that has that component**, as in Unreal's Details panel: typing a position puts them all at that position; an entity without the component (the Sun has no MeshRenderer) is skipped without an error; a name is never copied. The edits share one undo group, so one Undo takes all of them back. A single click anywhere collapses the selection onto one entity; an entity that is deleted leaves the selection.

## Snapping

The right end of the scene toolbar has three drop-down pills, as Unreal's viewport has: **Move** (off, 0.1, 0.25, 0.5, 1, 5, 10 m), **Rotate** (off, 5, 10, 15, 30, 45, 90 degrees) and **Scale** (off, 0.05, 0.1, 0.25, 0.5, 1). With a step chosen, the Move handle puts the position on a multiple of it, the Rotate ring turns by a multiple of it and the Scale handle ends on one (never below one step). With a step **off**, holding **Ctrl** still snaps to the usual 0.5 m, 15 degrees and 0.1.

## Paint mode (Unreal's Foliage mode, small)

Right-click a row of the **Place** tab (a cube, a sphere, a cylinder, an empty, a light, a sprite, an audio source, an emitter) and choose **Paint with this**, or right-click a model in the **Project** panel and choose **Paint with this model**. A brush bar appears at the top of the Place tab (what is painted, **Radius** and **Spacing** in metres, **Stop**), a banner at the top of the scene view, and a ring of the brush's size follows the pointer over whatever it is over. **Drag with the left button** over the scene: the stroke collects a point every *spacing* metres and, when the button is let go, a number of copies (about the number of spacing-squares in the circle, thinned a little) is scattered round every point, each standing on what is under it (a ray from above finds the floor, the terrain or a roof), with a turn of its own about the vertical and a scale between 0.8 and 1.2 (a light or a sound keeps its size). The whole stroke is **one** `batch` call, so **one Undo** takes it back; a click without a drag is a stroke of one point; one stroke makes at most 2000 copies. While a brush is armed the left button paints instead of picking and dragging handles (the camera keys and the right button work as always); **Esc** (or **Stop**) puts the brush down. The copies are named `Cube 1, Cube 2, ...` (the numbers continue those in the scene) and are plain entities, so everything else works on them: select, move, group, save.

## The UI tab (Unreal's UMG look)

The **UI** tab is a designer for the on-screen interface (`docs/UI.md`), in the manner of Unreal's widget designer. The left panel becomes the **Palette** (Button, Text Block, Progress Bar, Border) over the **Hierarchy** of the widgets (front to back, the eye hides one, double-click renames, right-click deletes), the right panel **Details**, and the middle the **Designer**: the screen as a frame (*Screen Size* picks 1920 x 1080, a phone in portrait, ...) with the widgets drawn as the game draws them.

* Drag a palette entry onto the screen to add a widget there (or click it to add one in the middle, or right click the screen). Click a widget to select it; drag it to move it; drag a white handle to resize it. Positions snap to an 8 pixel grid (`Alt` turns the snap off; `Snap` and `Grid` are toolbar buttons). Arrow keys nudge by one pixel (`Shift`: eight), `Delete`, `Ctrl+D`, `Ctrl+Z` / `Ctrl+Y` work as in the scene view; the wheel zooms, the right button drags the view; *Zoom to Fit* resets it.
* **Details** has the *Slot* (position, size and ZOrder in pixels of the chosen screen), *Appearance* (colour and opacity, background colour, fill percent for a bar, border), *Content* (the text with `{resource}` placeholders, its size and colour) and *Behavior* (visible, is a button).
* The widgets are the `Ui` entities of the scene: every change is a `set`, `spawn` or `despawn` tool call, so undo, recordings and an agent working in the same world all see it; one drag is one undo step. **Graph** (top right) switches to the Blueprint tab, where the systems that react to `Ui.clicked` are nodes.

## The Blueprint tab (Unreal's look)

The **Blueprint** tab edits a graph system (`docs/GRAPH.md`) as nodes, the way Unreal Engine's Blueprint editor does. The left panel becomes **My Blueprint** (the graph systems of the world, and its resources: click one to add a *Get Resource* node), the right panel **Details** (the properties and default values of the selected node, the system's own settings when nothing or the red event node is selected). In the graph:

* The red **event node** starts the system (*Every Tick* or *On Contact*). White **execution** wires run from node to node and say what happens after what; **Branch** has *True*, *False* and *Completed* (what comes after both).
* **Data pins** are round: green numbers, red true/false, pink text. A wire carries a value from the output of one node into an input of another. An input with no wire holds a value of its own: click the box next to its name and type it (a check box for true/false).
* Properties such as the field of *Set Field* are rows at the foot of the node; click one to type. *Spawn Entity*, *Add Component* and the maths nodes with any number of inputs have **+ Add pin**; double-click the name of a spawn pin to rename it (`Transform.pos`).

| | |
|---|---|
| Right button drag, wheel | Pan, zoom around the pointer |
| Right click | The **All Actions** menu with a search box (`Emit`, `Add`, `Branch`...); on a node, a pin or a comment, the menu of that. Dropping a wire on an empty place opens it with only what fits the pin. |
| Left drag | A node (header or body) moves, an empty place draws a selection box, from a pin pulls a wire (onto another pin to connect; an input that already has a wire gives it up and you can move it); `Alt` + click on a pin breaks its wires |
| `Delete`, `Ctrl+D`, `Ctrl+C` / `Ctrl+V`, `Ctrl+A` | Delete, duplicate, copy and paste, select all; `Ctrl+Z` / `Ctrl+Y` undo and redo (of the graph) |
| `C`, `F` | A comment box around the selection (drag its title to move it with what it holds, the corner to resize it, double-click the title to rename it); frame the selection |
| `Ctrl+S`, **Compile** | Checks the graph (a missing field name, a circle of wires: shown on the node, with a list in *Compiler Results*) and sends it to the world with `define_system`. What the *world* refuses (an unknown component) comes back with its place in the graph when it can be found. |
| **Arrange**, **Frame All**, **Edit as Script** | Lay all nodes out again, show all of them, open the same system as text in the Script tab |

**Live values.** Select an entity (in the Hierarchy or the scene view) and every data node of the open graph shows the value it had for that entity, in a small box at its output pin: the number a `Get` read, what an `Add` made of it, whether a condition was true (green) or false (red), so you can see which way a Branch went and why. It updates a few times a second while the game plays (and twice a second in edit mode, from the scene as it is), follows the graph **as you edit it** (an edit that is not compiled yet shows its values too), and changes nothing in the world: the editor asks the `trace_system` tool, which runs the system once for that entity on a throwaway copy (`docs/GRAPH.md`). The top bar says whose values these are (`live: entity 12, tick 340`), that the selected entity is not visited by this system (it lacks a component of its *each* list), or what stopped the run (`stopped: division by zero`; the values found before it are still shown). Nothing is shown for systems of touching pairs (`on_contact`), for a graph with problems, or in a scene of more than 100 000 entities.

**Breakpoints.** Right click a statement node (Set, Let, Branch, Emit ...) > *Add Breakpoint*, or select it and press **F9**: a red dot appears on its header. Select an entity and press Play: after every tick the editor asks what the *next* tick of this graph will do for that entity, and **when it is about to run a statement that has a breakpoint the game pauses before the statement runs** (the state you see is the state the statement will see), the node gets a red outline and *STOPPED HERE*, the top bar says so, and the Compiler Results log says which node and which tick. **Play** goes on and **Step** runs one tick (the next stop, if the same statement runs again, comes after it). Statements that ran (or run next) for the selected entity have a green outline, so which way a Branch went can be read off the graph. Breakpoints belong to the graph on the screen, not the file (compile it so that the game runs what you stopped in), are not kept when the editor closes, and are only checked for the selected entity, in a scene of at most 20 000 entities (a check copies the world), for systems that visit entities one at a time (not `on_contact`); stopping the game clears the mark.

Nodes that are not wired to the event do nothing and are dimmed (*not connected*). Where nodes are, and the comment boxes, are kept in `blueprints/<system>.bp.json` of the project; the file is used only while it says the same thing as the system in the world. Anything the nodes have no words for stays as a **Raw** node holding its JSON, so no system is ever too odd to open. The nodes, the JSON and the script (`docs/SCRIPT.md`) are three views of one system, and each can open any system of any scene (`cargo test -p lunaris-studio blueprint` runs every example scene through the nodes and back).

## The Effects tab (Unreal's Niagara editor, small)

The **Effects** tab edits the effects of `ParticleSystem` (`docs/FX.md`), which are JSON files (`*.fx.json`). **The left panel** lists the effect files of the workspace (New makes one from a small template; Refresh looks again). **The middle** has the controls (Save, Revert, Play and Pause, Restart, the speed, whether an effect that ends starts over, the floor), then a **preview**: the effect playing on a small private stage (a floor, a sun, a camera at a distance that fits the effect), drawn by the reference renderer (so no soft particles, bloom or card emitters; the emitters that ask for the card are stepped on the processor in the preview), and under it the **text** of the effect. Every change of the text is read at once: a mistake is the reader's own message in red, with the place in the document (`emitters[0].spawn.rate: -3 is outside 0 to 1000000`), the last good picture stays dimmed in the preview, and warnings (an unknown key, with the nearest one) are shown in yellow. **Save** (or Ctrl+S) writes the file; a running game reads it again within half a second. **The right panel** has "Use this effect on it", which puts the effect on the entity selected in the scene (as its file once it is saved, else the JSON itself; through `set`, or `add_component` when the entity has none, so Undo and the Console see it), and the effect of the selected entity with an Open button; then the emitters of the effect as a list, with what the chosen one does (space, rate, bursts, lives, speed, size, how it is drawn, events) and its **curves drawn** (size, opacity, speed, light, and the colour over the life as a strip). Switching to another file with unsaved changes asks you to save first. What is left: dragging keys on the curves, an emitter list that adds and removes emitters without typing JSON, a preview on the GPU renderer ([EDITOR_AUDIT](EDITOR_AUDIT.md)).

## The Sequencer tab (Unreal's Sequencer, small)

The **Sequencer** tab shows the `Timeline` of the selected entity (`docs/GAMEPLAY.md`, "Timelines": a script of `at SECONDS ACTION` lines) as tracks over a time ruler. Every number the script moves has a lane named by its path (`Transform.pos[1]`, `Light.intensity`, `res score`, `events`); a **ramp** is a coloured bar from its start to its end with the numbers it goes between (and its easing), a `set`, a resource step or an event is a diamond with its value or name, and `end` is a red line across all the lanes. An entity without a Timeline offers to get one.

| | |
|---|---|
| Drag a bar or a diamond | Moves the step in time (snaps to 0.05 s, **Shift** for free) |
| Drag the right edge of a bar | Changes how long the ramp takes |
| Double-click a step, or right click > Edit | A window for its numbers and names: when, the path, from and to, the easing (0 to 13, as in `Tween`) |
| Right click > Duplicate, Delete | Copy a step half a second later; remove it |
| **+ Add step** | A ramp, a set, an event, a resource step or the end, put at the playhead |
| Click the ruler or an empty place, or drag the playhead | Scrubs: moves the playhead to that second |
| Wheel, Ctrl + wheel, the zoom slider | Scroll in time, zoom |
| **Loop**, **speed** | The timeline's `looping` and `speed` |

**Preview.** In edit mode scrubbing moves the playhead and nothing else, because the scene is the author's and a scrub must not change what gets saved. **Preview** starts a play session that is paused (like Play, then Pause); in it every scrub puts the scene where the sequence would have it at that second (`timeline_seek`: ramps by their progress and easing, `set` steps as of then, no events), so you can see a cutscene's pose at any time and judge its easing. **Stop preview** (or Stop) puts everything back exactly as it was. Every edit is written into the entity's `Timeline.script` as text, so the tab, the text in the Inspector and the engine are one thing: a line the sequencer does not understand, a comment or a blank line stays where it is, and a step you did not touch keeps its text (and its comment).

Not there yet: curves between keys (a ramp is two numbers and an easing), several entities in one sequence (a Timeline moves the fields of its own entity), camera cuts, audio tracks, and keyframing from the Inspector (right click a field to key it).

## The Script tab (Visual Studio Code's look)

The **Script** tab next to Scene and Game is a code editor for **Lunaris Script** (`docs/SCRIPT.md`), drawn the way Visual Studio Code draws: an activity bar, an Explorer with the scripts of the project (`scripts/*.lun`) and the graph systems of the scene, tabs for the open files, breadcrumbs, line numbers, indent guides, a minimap, squiggles under mistakes, a Problems and an Output panel, a status bar. The colours are not imitated: the tab reads the theme files VS Code itself reads (`colors` and `tokenColors`, with `include` chains). **Dark 2026**, **Dark Modern**, **Dark+** and **Visual Studio Dark** are built in (`crates/lunaris-studio/assets/vscode`, MIT licence), and `Ctrl+Shift+P`, *Preferences: Color Theme* lists every dark theme of an installed VS Code and of its extensions, previews each as you move through the list, and remembers the choice in `.lunaris/editor.json`.

| | |
|---|---|
| `Ctrl+S` (or the triangle) | Compiles, defines the systems with `define_system` and saves the file. A mistake of the text is a red squiggle with a line and column; one the world finds (an unknown field) is shown at the same place. A system that is no longer in the script is removed from the world. |
| `Ctrl+Shift+P`, `F1` | The command palette: apply, new script, find, go to line, format document, toggle minimap and Problems, colour theme |
| `Ctrl+P` | Quick open: a script file or a system of the scene |
| `Ctrl+F`, `Ctrl+G`, `Ctrl+W`, `Ctrl+B`, `Ctrl+Shift+M` | Find (with match case), go to line (`:12` in the palette too), close the tab, side bar, Problems |
| Typing | Completion for keywords, functions, components, the fields of a component after its dot, local variables, `$resources`; `Ctrl+Space` asks for it. Brackets and quotes close and are stepped over, Enter keeps the indentation and opens a block, Tab and Shift+Tab indent, `Ctrl+/` comments lines, hovering a squiggle shows its message |

The Systems panel has **Edit as script** for the system it shows. The text, the node view and the JSON are three views of one system (`docs/SCRIPT.md`).

## The Project panel: thumbnails and dragging into the scene

A **picture's tile shows the picture**, shrunk to at most 64 pixels on its long side (a box filter, so a checker of fine lines goes grey instead of aliasing; hidden colour under transparency does not bleed in). A **sound's tile shows its waveform** (WAV, Ogg Vorbis and MP3 are read): one column for each stretch of the clip, mirrored about the middle, the peak in a pale teal and the average loudness in a stronger one, scaled so that the loudest moment reaches the edge (at most 20 times up, so a quiet sound's shape shows; silence is a thin line). A **model's tile shows the model**: `lunaris_render::thumb::thumbnail` draws the imported mesh from a fixed three-quarter view (from the front, a little to the right and above) with a depth buffer and one light, in the material's colours and base texture (an alpha cut-out leaf stays cut out), into 96 x 96 pixels, drawn at twice the size and averaged down for smooth edges. It is a plain CPU rasteriser, so it needs no graphics card and no scene. Both are made on worker threads, three at a time, so the panel never waits; a tile shows its icon until its thumbnail is ready, and a file that the decoders do not take (or a picture over 24 MB, a model over 64 MB) keeps its icon. A file that changes (another size) is read again. A decoder that panics on a broken file leaves the icon instead of a tile that waits for ever.

**Dragging.** Press on the tile of a model, picture or sound and drag: the file's name hangs at the pointer, and over the scene view the whole view gets an outline and a label says what letting go will do:

| What is dragged | Where it is dropped | What happens |
|---|---|---|
| a **model** (`.glb`, `.gltf`) | the scene view (3D) | a new entity named after the file with a `MeshRenderer` on the model, standing **with its lowest point on whatever is under the pointer** (the ray through the pointer is cast at the scene, the ground plane y = 0 takes it when it hits nothing; the model's bounds, from `model_info`, say how far to lift it, whatever the author's origin is), and it is selected |
| a **model** | the 2D view | the same, on the plane z = 0 |
| a **picture** | a mesh in the scene view | the picture becomes that mesh's `MeshRenderer.texture` (what is under the pointer is read from the same picture-of-ids that picking uses; on anything that is not a mesh the label says "drop it on a mesh" and nothing happens) |
| a **sound** | the scene view | a new Audio Source at that point that plays the file |

Escape while dragging, or letting go anywhere else (the Hierarchy, the Inspector, the Project panel), does nothing. A drop is a tool call (`spawn`, `set`), so one Undo takes it back and a recording or an agent in the same project sees it. The right-click menu does the same without the pointer (**Add to the scene**, **Add as an Audio Source**, **Use on the selected mesh**), the model at the origin, standing on y = 0. The dropped entity is made while the game is not playing (during play the view takes no drops: whatever the session adds is gone when it stops).

## Pictures of the editor without a window

The window needs a graphics card and a screen; the tests have neither. `crates/lunaris-studio/src/shot.rs` draws what egui hands over (its textures, and its shapes cut into triangles by egui itself) in software, with the window's blending, so that the editor can be looked at from a test run on a Linux test machine: `LUNARIS_SHOTS=/tmp/shots cargo test --release -p lunaris-studio screenshots -- --nocapture` writes 1600 x 900 PNGs of the Caldera example in every tab (the scene with model thumbnails, the Place tab, several things selected, a model carried over the scene and dropped, Blueprint, Script, Sequencer, Game, UI, Canvas, Project Settings, the Profiler while playing). Without `LUNARIS_SHOTS` the test does nothing. The scene view's picture is the CPU reference renderer's, so it shows what the engine draws, not the graphics card's version of it. Looking at these found a status text in the Blueprint toolbar that was drawn over the buttons when the middle panel was narrow (now cut short with three dots).

## Project Settings

**Edit > Project Settings...** opens a window with what the game is apart from its scenes: its **name** (empty: the name of the scene), the **start scene** (a drop-down of the scenes of the workspace; the default is the scene that is open when the game is built), the **quality** it asks for (classic to ultra), the **window size** and the **seed** of its simulation. They are saved in `project.lunaris.json` at the root of the workspace (plain text, so it goes with the project into version control) when you press Save or close the window, and a new editor on the same workspace starts with them. Build Windows Player uses them; `lunaris-editor scene.json --build Game.exe` too (a workspace without the file is built at the quality given by `--quality`).

## Building a game

**File > Build Windows Player...** asks for a name and a folder (the name comes from the project settings) and makes the game as a program there: `<Name>.exe` (a copy of the Lunaris player, which has no console window), `game.json` (which scene to open, the quality, the window size and the seed, from the project settings), the scene as it is in the editor right now, and every file the scene mentions (pictures, models, sounds, WebAssembly modules) at the same relative paths. The folder runs on a machine that has nothing else of Lunaris on it: double-click `<Name>.exe`. **Build and Run...** starts it at once. The player is `lunaris-player.exe` (next to the editor; `lunaris-player scene.json` plays a scene from the command line).

## Everything is a tool call

The editor never touches the world by itself: it calls `spawn`, `set`, `despawn`, `snapshot`, `restore`, `undo` ... exactly as an AI agent or `lunaris call` does. So undo and redo cover whatever you or an agent did, a recording made with `record_start` contains the editor's edits, and an agent connected to the same project through MCP sees the same engine. A drag of a handle is many `set` calls with one `undo_group`, so it is one undo step.

## Keyboard

Q W E R tools - F frame the selection - Ctrl+Z / Ctrl+Y undo, redo - Ctrl+D duplicate - Delete - Ctrl+S save - Ctrl+O open - Ctrl+N new - Ctrl+P play and stop - Esc stop.

## Command line

`lunaris-editor [scene] [--root DIR] [--seed N] [--size WxH] [--quality classic|low|medium|high|ultra|reference] [--select NAME] [--play] [--mute] [--tab project|console|systems] [--view scene|2d|game] [--shot FILE [--shot-delay SECONDS]]`. `--shot` saves a picture of the window and quits (the documentation and the tests use it). Windows only for now; the engine, the tools and the browser editor below run elsewhere.

## The Canvas tab

A board for plans and maps, in the editor: notes, groups and arrows on an endless surface. The files are `*.canvas` in the JSON Canvas format (the one Obsidian reads and writes: `nodes` of type `text`, `file`, `link` and `group`, and `edges` with a label and a colour), so a canvas made there opens here and the other way round; fields the editor does not know are kept when it saves.

* **Open** one from the list in the tab's toolbar (every `.canvas` file of the workspace), or start the editor with `--canvas FILE` (or `--tab canvas`). The game plan of `examples/wyrdwood/` is one: `lunaris-editor --canvas examples/wyrdwood/wyrdwood.canvas`.
* **Move around**: drag the background (or the middle button) to pan, scroll to zoom around the pointer, `F` or the **Fit** button shows the whole board. Far away a note shows only its first line, so the shape of the board still says what is where.
* **Edit**: click a note, then change its text (a little Markdown: `#` headings, `-` bullets, `**bold**`, `` `code` ``, `[[links]]` shown as their text), colour (Obsidian's six presets), position and size in the **Details** panel; drag a note to move it (dragging a group takes what is inside it); **+ Note** and **+ Group** add one in the middle of the view; right-click the board for a note where the pointer is; `Delete` removes the selected note and its arrows. `Ctrl+S` or **Save** writes the file.
* **Notes** (the left panel) lists the notes in order with a search box: click one to select it and bring it to the middle.
* **It follows the file**: when another program saves the open canvas (an agent keeping a plan up to date) and the board has no unsaved changes, the editor reads it again and keeps the view and the selection. With unsaved changes of its own it never throws them away.

Arrows are drawn and shown in the Details of the notes they join; they are not edited in the editor yet (edit them in the file or in Obsidian). Code: `crates/lunaris-studio/src/canvas_ui.rs`.
