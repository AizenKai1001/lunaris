# The editor against Unreal's: what is there, what is missing

Section 3 of [ROADMAP](ROADMAP.md) asks for an audit of the editor against Unreal's: which part of Unreal's editor has an equivalent in Lunaris Editor today, and what the gap is. This is that table, dated **2026-10-25**. It was made by reading [EDITOR](EDITOR.md) and the editor's source (`crates/lunaris-studio`) and by running its test suite (61 tests, which drive the editor with synthetic pointer and key events); nobody has sat in front of every panel for this audit, so a "has" means "documented and tested", not "polished". The look follows Unreal's panels (Unity's layout for the main window, Unreal's for the Blueprint and UI tabs, VS Code's for the Script tab); the rule for the gaps is the roadmap's: simple first, optional depth after, and no picture drawn by hand (images the editor needs come from image generation).

| Unreal editor part | Lunaris Editor today | Gap | Size |
|---|---|---|---|
| **Outliner** | Hierarchy: every entity, children under their parent, search, rename, drag to attach, duplicate, delete, detach, create | multi-select is there (2026-10-25: Ctrl and Shift click, move, duplicate, delete and frame act on all; values typed in the Inspector go to all that have the component; the Rotate and Scale handles act on the main one); no folders or groups; no visibility or lock toggle per entity; no filter by component type | M |
| **Details panel** | Inspector: every component as a foldout, every field as the right widget from the engine's schema, add and remove component, angles for rotation | no multi-edit of several selected entities; no reset-to-default per field; no search box over fields; no copy and paste of a component's values | M |
| **Content Browser** | Project panel: folders, tiles, double-click a scene to open, right-click a model, sound or picture to use it | pictures, models and sounds (a waveform) show a thumbnail and a model, picture or sound can be dragged into the scene view (2026-10-25); scenes keep an icon (a preview is next); a type menu narrows the tiles (2026-10-25); no drag of a scene or a prefab; no drop onto the Hierarchy to attach; no "where is this used" | M |
| **Viewport** | Scene view: fly camera, orbit, pan, frame (F), Q W E R tools, axis handles with snapping, 2D mode, grid, render-quality picker, game view | no GPU draw-call count in the **Stats** overlay (frame time, picture time, entities, tick and the fly speed are there, 2026-10-25); no camera bookmarks; no local/world space switch; no snap-size settings in the interface; no orthographic top/side views | S–M |
| **Play in Editor** | Play, Pause, Step; the scene is snapshotted and comes back exactly (same state hash); sound and input go to the game | no "simulate" that keeps edits made while running; no several-players run against a local server; no play-settings (window size, start camera) | M |
| **Undo and redo** | Every edit is a tool call, so undo covers what you or an agent did; one drag is one undo step | no history list to jump back several steps | S |
| **Blueprint editor** | Blueprint tab: event node, execution and data wires, branches, All Actions search, comments, copy and paste, compile with a list of problems, arrange, round trip with JSON and script | live values on the wires of the selected entity are there (2026-10-25, from `trace_system`); no variables, functions or macros (a graph is one system); breakpoints on statements (pause before one runs for the selected entity) are there (2026-10-25); no conditional breakpoints (break when a value is a chosen one) and no stepping inside a tick; no event dispatchers; no reroute nodes | L |
| **Code editing** | Script tab in VS Code's look, real VS Code themes, completion, problems, command palette | no debugger in the text editor | M |
| **UMG widget designer** | UI tab: palette, hierarchy, details, designer with snapping and screen sizes | no animations for widgets; no widget templates beyond the four basics; no style sets | M |
| **Material editor** | none: materials are fields (colour, metallic, roughness, texture, clearcoat, sheen, subsurface) in the inspector | a node graph for materials, a preview sphere, texture parameters | L |
| **Animation (Persona) and Sequencer** | **Sequencer tab (2026-10-25)** over the `Timeline` component: lanes, ramp bars, key diamonds, drag to move and resize, scrub with a preview, edit windows, written back as the script's text. Clips can be played and warped by components, not edited | curves between keys, several entities in one sequence, camera cuts, audio tracks, keying a field from the Inspector; a state-machine view; clip editing (Persona) | M for the rest of the Sequencer, L for Persona |
| **Niagara (particles)** | **Effects tab (2026-10-26)** over `ParticleSystem` and its JSON effects ([FX](FX.md)): the effect files of the workspace, the text with the reader's messages at once, a preview that plays on a stage of its own, the emitters of the effect with their curves drawn, Save, and "Use this effect on it" for the selected entity; the Inspector still shows the component and `check` reads the effect | dragging keys on the curves; adding, removing and reordering emitters and modules without typing JSON; a preview on the GPU renderer (soft particles, bloom, card emitters); a graph view of the emitter stack | M |
| **Profiler (Stat, Insights)** | **Profiler tab (2026-10-25)**: live game-thread stages while playing, average and slowest tick, headroom against 60 Hz, history graph, advice | no GPU time per pass; no memory view; no capture to a file and no loading of captures; no flame graph; no network view | M |
| **Project Settings** | **Edit > Project Settings (2026-10-25)**: game name, start scene, quality, window size, seed, saved in `project.lunaris.json` and used by the build | input map, physics, audio, build targets and server settings are not in it yet | S |
| **World Settings, level streaming, World Partition** | the engine streams zones and a city; the editor does not show them | a view of streaming zones and their state | M |
| **Landscape and Foliage tools** | terrain is made outside (heightmaps, layers) and loaded | in-editor sculpt and paint | L |
| **Output Log** | Console: every tool call with arguments and answer, errors in red, search, "Check scene", a box to type any tool call | log levels and categories for game messages | S |
| **Packaging** | File > Build Windows Player, Build and Run | other platforms from the editor; a packaging settings page | M |
| **Source control** | none in the editor (the project is plain text and files: use git) | a status column in the Project panel | S |
| **Place Actors** | the **Place** tab of the left panel (2026-10-25): click or drag a template into the scene | no custom palettes (prefabs and scripts as rows), no recently placed list | S |
| **Layout** | fixed docking with panel toggles | drag panels, save and restore layouts | M |

Sizes: **S** is a day or less, **M** a few days, **L** a week or more.

## What to do first, and why

1. ~~**Viewport statistics and camera speed** (S)~~ **done 2026-10-25**: the Stats toggle and the wheel-sets-fly-speed (draw-call counts from the GPU renderer are left).
2. ~~**Project Settings window** (M)~~ **done 2026-10-25** (the five settings a built game reads; the rest follow as the engine grows settings worth editing).
3. ~~**Content Browser thumbnails and drag into the scene**~~ **done 2026-10-25**: thumbnails for pictures and models (a small CPU render, made on worker threads) and dragging a model, picture or sound into the scene view; a "where is this used" is left (sounds got waveforms and the panel a type menu the same day).
4. ~~**Blueprint live values**~~ **done 2026-10-25** (`trace_system` and the values at the output pins); **breakpoints on statements done 2026-10-25** (pause before a statement runs for the selected entity); conditional breakpoints (a value is a chosen one) are the next step.
5. ~~**Multi-select**~~ **done 2026-10-25** (selection, move, duplicate, delete, frame); the Inspector writes a changed value to every selected entity that has the component (done the same day); rotate/scale handles for the group, and showing "multiple values" where the selection differs, are the rest.
6. **Material editor** (L) and **the rest of the Sequencer** (keying from the Inspector, curves, several entities; M). The first Sequencer (2026-10-25) is a timeline over the script the engine already runs; the material editor needs a design pass before any code, and generated pictures for its icons.

Everything on this list keeps the rule that the editor only ever calls tools (so undo, recordings and an agent in the same project see what the editor does); a gap that needs a new tool starts with the tool.
